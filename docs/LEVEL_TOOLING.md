# 关卡设计工具调研

> 日期：2026-10-29  
> 目标：解决当前「10 关闯关」关卡迭代慢、难度靠手调、无法快速验证的问题。

## 1. 结论先行

**不建议直接上 Tiled / LDtk / Ogmo 作为主工具。**

当前关卡的核心不是“画地图”，而是：

- 圆形触发区 + 透视投影
- 移动门 / 重叠门
- 每关独立预设冰球
- 伤害 / 钉子 / 门三种目标
- 物理结果与瞄准路线强相关
- 需要快速试玩和通过率验证

这些是**玩法专用数据**，通用地图编辑器只能解决“摆位置”，解决不了“这关到底能不能过、难度是不是太高”。

**推荐方案：在现有 HTML5 原型里做一个专用关卡编辑器 + 难度模拟器，导出 JSON；Cocos 阶段复用同一份 JSON。**

投入约：

- 0.5 天：把硬编码 `CAMPAIGN_LEVELS` 抽成 `levels.json`
- 2~3 天：专用编辑器 MVP（拖门、拖钉、球预设、目标、试玩、导出）
- 1~2 天：批量模拟 + 难度指标
- 3~5 天：用工具重做 10 关
- 1 天：Cocos JSON 导入

比“接 Tiled/LDtk + 写导入器 + 仍然不能一键试玩”更快，而且能直接解决关卡问题。

## 2. 当前瓶颈诊断

现在 `game.js` 里的 10 关是**硬编码 JS 数据**：

- 改一个门的位置要改代码、刷新、重进关卡
- 改完无法知道“中心路线能不能过、侧边路线收益多少”
- 目标值靠单次手测，随机 build/瞄准的通过率未知
- 门圆、钉阵、预设球、目标之间没有校验
- 没有版本对比，改坏了只能 git diff
- 没有批量试玩，无法画难度曲线

所以真正缺的不是“一个能摆对象的编辑器”，而是：

1. **可视化编辑**
2. **一键试玩**
3. **一键批量模拟**
4. **同一份 JSON 给 Cocos**

## 3. 工具分类

| 类别 | 工具 | 解决什么 | 不解决什么 |
|---|---|---|---|
| 通用 2D 关卡编辑器 | Tiled、LDtk、Ogmo | 摆 tile / entity / 对象层 | 本游戏物理、圆形触发、目标、通过率 |
| 引擎内编辑器 | Cocos Creator Scene / Prefab / 扩展 | 最终场景、美术、组件 | 快速批量调数值、自动试玩 |
| 电子表格 | Google Sheets / Excel / CSV | 数值表、难度曲线 | 布局、试玩 |
| 模拟工具 | Machinations | 经济/成长/资源循环 | 空间布局、物理 |
| 专用编辑器 | 自研 Web Editor | 本项目全部需求 | 需要开发 |
| 试玩/遥测 | PlaytestCloud、UserTesting、抖音数据分析 | 真人通过率、卡点 | 设计生产效率 |

## 4. 通用编辑器横向对比

| 工具 | 布局能力 | 实时试玩 | 数据导出 | Cocos 接入 | 适合本项目 | 主要问题 |
|---|---|---|---|---|---|---|
| **Tiled** | 强（tile + object layer） | 否 | TMX/JSON | Cocos 原生 TiledMap 主要支持 tile layer；object layer 仍需自定义解析 | 2/5 | 非 tile 玩法，导入器成本高 |
| **LDtk** | 很强（Entity、自定义字段、Level 字段、JSON Schema） | 否 | 纯 JSON | 无官方 Cocos 导入，需要自己写 | 3/5 | 最接近，但仍不能一键试玩/模拟 |
| **Ogmo 3** | 强（Entity / Decal / Grid） | 否 | JSON | 无官方 Cocos 导入 | 2/5 | 社区版维护弱，通用导入器成本 |
| **Cocos Scene/Prefab** | 中（引擎内） | 可运行 | 场景/预制体 | 原生 | 3/5 | 10 关逐个搭场景慢，批量调数值难 |
| **Cocos 编辑器扩展** | 可定制 | 可接预览 | 自定义 | 原生 | 4/5 | 开发成本高于 Web MVP |
| **自研 Web Editor** | 完全贴合 | 是 | JSON | 自定义导入 | 5/5 | 需要 2~3 天开发 |
| **表格** | 无 | 否 | CSV/JSON | 易 | 3/5 | 只能数值，不能布局 |

### 4.1 Tiled

优点：

- 成熟、稳定、免费，对象层支持矩形、椭圆、点、多边形、自定义属性
- JSON 格式清晰，适合存门/钉子/出生点
- Cocos Creator 3.8 有 TiledMap 组件，但**原生主要面向 tilemap**；对象层、自定义实体仍要写导入逻辑
- 如果未来关卡变成 tile-based 或需要外部关卡设计师，Tiled 是首选

不适合当前项目的原因：

- 圆形触发区、透视投影、移动门、每关预设球、三种目标都不是 Tiled 原生概念
- 编辑器里看到的圆，不等于游戏里的屏幕圆/物理判定
- 不能一键试玩，不能批量跑通过率
- 10 关规模，写 Tiled 导入器 + 维护映射的钱，可能比自研编辑器还高

### 4.2 LDtk

优点：

- 现代 2D 编辑器，Entity 可显示矩形/圆/点，支持自定义字段和 Level 自定义字段
- 纯 JSON，带 JSON Schema，数据结构适合程序读取
- 支持世界/多关卡、自动图层、实体标签
- 比 Tiled 更适合“实体驱动”的非 tile 玩法

不适合当前项目的原因：

- 没有 Cocos 官方导入；需要自己写 Entity -> 门的映射
- 仍然不能一键试玩本游戏
- 不能在编辑器里看到冰球实际路径、门触发概率、目标能否达成
- 对 10 个高度定制的关卡，学习/维护成本高于收益

**如果未来关卡数量扩展到 50+、需要外部关卡设计师协作，LDtk 是通用工具里最值得选的。**

### 4.3 Ogmo Editor 3

优点：

- 免费、开源、MIT，Entity/Decal/Grid 层，JSON 输出
- 为独立游戏设计，项目制工作流舒服

不适合：

- 社区版维护弱
- 没有 Cocos 导入
- 同样不能试玩/模拟
- 生态和文档不如 Tiled/LDtk

### 4.4 Cocos Creator 内建编辑器 / 扩展

优点：

- 最终引擎原生，所见即所得
- 3.8 支持编辑器扩展、面板、菜单、Inspector
- 可以直接把最终的 prefab/节点结构做出来

不适合当前阶段：

- 做 10 关需要反复搭建场景/预制体
- 批量改数值、批量模拟、版本对比不如 Web 工具
- 扩展开发成本高于现有 Canvas 原型加编辑器

**定位：最终美术/表现/抖音构建阶段用 Cocos；关卡数据和难度迭代仍在专用工具里。**

## 5. 推荐：专用 Web 关卡编辑器

### 5.1 为什么是自研

本游戏关卡的数据维度很少但很特殊：

```
goal + balls + rows(gates) + pins + moving + spawn/release
```

做一个只服务这 5 类数据的编辑器，比接通用工具简单得多。

编辑器可以直接复用游戏代码：

- 同一个 `project()` 透视投影
- 同一个圆形触发判定
- 同一个物理模拟
- 同一个球/门/钉渲染
- 同一套关卡 JSON

做到“编辑即试玩，试玩即数据”。

### 5.2 MVP 功能

**布局**

- 俯视 / 透视两种视图切换
- 拖动门圆心、调直径、拖整排 y
- 门类型选择：变大 / 分裂 / 加速 / 倍率 / 磁铁 / 穿透 / 缩小 / 粘滞
- 移动门：振幅、速度、相位，编辑器内实时预览
- 钉子：预设阵型（菱形 / 稀疏 / 墙 / 双簇 / 环 / 密阵 / 首领）+ 单点拖动
- 出生点、营垒、轨道固定参考线

**关卡参数**

- 关卡名、目标类型、目标值
- 预设冰球：类型、数量、等级
- 初始镜头/背景/主题
- 关卡提示文案

**编辑效率**

- Undo/Redo
- 复制关卡 / 另存变体
- 自动保存 localStorage
- 导入/导出 JSON
- 关卡列表 + 缩略图
- 快捷键：删除、复制、微调

**校验**

- 门是否超出轨道
- 第一排是否覆盖出生点
- 门圆是否完全在可触发区域
- 球数量是否 ≥ 1
- 目标是否可能（根据模拟）
- 钉阵是否越界
- 移动门振幅是否导致出门

**一键试玩**

- 从编辑器直接进入当前关卡
- 试玩结果回传：伤害、钉子、门数、剩余球、通关/失败
- 一键重试 / 返回编辑器

**导出**

- 单个关卡 JSON
- 全部关卡 `campaign-levels.json`
- 带 `schemaVersion`，方便 Cocos 导入

### 5.3 建议的数据结构

```json
{
  "schemaVersion": 1,
  "id": "campaign-05",
  "index": 5,
  "name": "重叠增益",
  "desc": "重叠圆一次吃两个 buff，触发 6 个门",
  "goal": { "type": "gates", "value": 6 },
  "balls": [
    { "id": "standard", "count": 1, "level": 1 },
    { "id": "split", "count": 1, "level": 1 }
  ],
  "rows": [
    {
      "y": 12,
      "gates": [
        { "type": "sizeUp", "x": 0, "w": 1.5, "move": null },
        { "type": "split", "x": 0, "w": 1.5, "move": null }
      ]
    }
  ],
  "pins": { "pattern": "diamond", "custom": null }
}
```

- `x/y/w` 使用世界坐标
- `move` 为 `null` 或 `{amp, speed, phase}`
- 钉子优先用 pattern，特殊关卡用 `custom` 数组
- 目标类型只允许 `damage / pins / gates`
- 渲染、判定、模拟都读同一份数据

### 5.4 难度模拟器

编辑器旁边加一个“跑 100 次”按钮：

- 对每个关卡批量模拟 N 次投掷
- 瞄准采样：
  - 中心
  - 左/右 ±0.3、±0.6、±1.0
  - 每个门圆心
  - 随机角度
- 旋转采样：-1 / 0 / +1
- 球顺序：按预设顺序 + 随机顺序
- 物理使用游戏同一套 `stepStone`、门触发、钉子、目标

输出：

```
关卡：第 7 关 风险之门
模拟：500 次
通关率：42%
平均用球：3.8 / 5
平均伤害：2610 / 2300
平均钉子：31
平均门：5.4
最差路线：中心直投（失败率 71%）
最佳路线：左侧巨力 + 右旋
```

**难度不应该由 DEF 定义，而应该由通过率 + 平均用球定义。**

建议目标带：

| 关卡段 | 通过率 | 平均用球 |
|---|---|---|
| 1~2 教学 | 80~95% | ≤ 50% |
| 3~5 入门 | 60~80% | 50~70% |
| 6~8 中段 | 40~65% | 60~85% |
| 9 高难 | 25~45% | 75~95% |
| 10 Boss | 15~35% | 80~100% |

这些数值可以按目标用户调整，但必须有数据，而不是“感觉难”。

### 5.5 关卡设计方法论

工具只是放大器，关卡设计仍要遵守：

1. **一关一个新动词**：瞄准 → 旋转 → 重叠门 → 钉阵 → 风险门 → 门收集
2. **先给安全路线，再给高收益路线**
3. **减益不放在唯一通路**
4. **每关目标只改变一个维度**（伤害/钉子/门）
5. **用通过率而不是 DEF 调难度**
6. **每关至少一个“可复述的决策”**：走左还是右？吃重叠还是吃倍率？保球还是冲？
7. **Boss 关考综合，不考新机制**

## 6. 工具组合建议

### 当前阶段（原型）

```
自研 Web Editor（主）
  + 游戏内试玩
  + 批量模拟器
  + JSON 文件
  + Git 版本管理
```

### Cocos 阶段

```
同一份 campaign-levels.json
  + Cocos 导入脚本
  + Cocos 场景/预制体做表现
  + 抖音真机试玩
```

### 需要外部关卡设计师时

```
LDtk 做粗布局/世界地图
  -> 导出 JSON
  -> 自己的转换器映射成 campaign-levels.json
  -> 游戏内模拟器验证
```

**不要让通用编辑器成为唯一数据源。** 游戏内模拟器才是难度真相。

## 7. 不建议的方案

- **直接把 Tiled tilemap 当关卡**：本游戏不是 tile 玩法，圆形门/移动门/物理都不匹配
- **只用 Cocos Scene 搭 10 关**：表现可以，批量调数值和模拟太慢
- **只用表格**：数值可以，布局和试玩不行
- **用 Machinations 做关卡**：它适合经济/成长模拟，不适合空间布局
- **换引擎**：当前瓶颈是关卡工具，不是引擎

## 10. 最终建议

**先做专用 Web 编辑器 + 批量模拟器，不要先接 Tiled/LDtk。**

当前关卡问题不是“没有地方摆门”，而是：

- 改一关太慢
- 不知道难度是否合理
- 不知道中心/侧边路线是否成立
- 没有通过率数据

专用工具能同时解决这三件事，而且导出的 JSON 可以直接给 Cocos。

如果只能选一个投资方向：**优先做“编辑 + 一键模拟”的闭环，而不是换一个更漂亮的地图编辑器。**
