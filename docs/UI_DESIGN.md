# UI / UX 设计说明（V2）

> 日期：2026-10-29  
> 目标：把原型 UI 从“能用”提升到“第一眼像正式产品、手机上顺手、信息一眼能读懂”。

## 1. 设计定位

关键词：**冰面、冷光、竞技、干净、可读**。

不是赛博朋克堆霓虹，也不是休闲游戏的大圆角糖果风。  
视觉方向定为 **Arctic Broadcast**：

- 深海军蓝背景
- 冰蓝主色 + 金色奖励色
- 半透明玻璃面板
- 细描边、低强度辉光
- 大数字、短文案、少装饰

## 2. 本次 UI 审计发现的问题

改造前：

1. HUD 顶部信息堆叠：分数、倍率、连击、门链、目标、壶数、按钮、DEF 徽章全挤在顶部
2. 主要操作和低頻操作没有层级
3. 顶部右侧按钮与抖音小游戏右上角胶囊区域存在冲突风险
4. 底部球条和旋转按钮是“漂浮按钮”，缺少容器和整体感
5. 选关页信息密度高，但缺少进度、当前关卡强调
6. 弹层缺少统一动效、焦点状态、无障碍处理
7. 字体尺寸偏小，部分 9~10px 文本在手机上难读
8. 触控目标部分只有 34~40px，低于 44px 推荐值
9. 关卡开始提示会换行、遮挡目标区
10. 没有明确的“主操作 / 次操作 / 低频操作”层级

## 3. 设计原则（调研结论）

### 3.1 拇指优先

手机游戏的主操作应在下半屏，低频操作可以放远。

- 主要操作：底部 dock（球条 + 旋转）
- 状态信息：顶部状态带
- 低频操作：顶部/侧边，但必须避开系统胶囊

参考：

- WANDR：拇指可达区在下半屏，顶部远角需要换握；反馈不能出现在手指下方
- Apple HIG Game Controls：常用控件至少 44×44 pt
- Google Playables：触控目标至少 48×48 dp，间距至少 8 dp

### 3.2 上下文极简

HUD 只保留“会影响当前决策”的信息：

- 分数 / 当前伤害
- 当前目标与进度
- 剩余球 / 剩余心
- 当前倍率、连击、门链
- 选关 / 重开 / 声音

不再在画布上重复绘制 DEF/目标徽章，避免和 HUD 抢位置。

### 3.3 清晰层级

每个屏幕只有一个主操作：

| 屏幕 | 主操作 |
|---|---|
| 主菜单 | 闯关模式 |
| 选关 | 当前可挑战关卡 |
| 游戏中 | 按住瞄准 → 松手投掷 |
| 过关 | 下一关 |
| 失败 | 重试本关 |
| 结算 | 选择关卡 |

次操作统一使用低对比描边按钮。

### 3.4 触控与安全区

- 交互目标最小 44×44 CSS px
- 按钮之间有 6~8px 间距
- 顶部/底部使用 `env(safe-area-inset-*)`
- 选关卡片高度 ≥92px，避免误触
- 弹层内容可滚动，避免小屏裁切

### 3.5 动效克制

- 弹层：280ms 上浮 + 淡入
- Toast：200ms
- 按钮：100~150ms
- 不做无意义的循环动画
- 支持 `prefers-reduced-motion: reduce`

参考：WCAG 2.2 / 2.3.3，交互动效应可关闭。

### 3.6 对比与可读性

- 正文目标 ≥ 4.5:1
- 大字号/粗体 ≥ 3:1
- 关键数字使用 tabular numerals
- 颜色不是唯一信息：门有图标 + 颜色 + 数值
- 锁定关卡不仅靠颜色，还带锁图标和“未解锁”文字


### 4.2 字号

| 层级 | 尺寸 |
|---|---|
| 品牌大标题 | 39px / 900 |
| 页面标题 | 30~34px / 900 |
| 按钮 | 13~16px / 800 |
| 正文 | 11~12px |
| 辅助信息 | 10px |
| 最小可读 | 10px（锁定/说明） |

### 4.3 圆角/间距

- 卡片：26~28px
- 按钮：15~17px
- 小控件：12~14px
- 页面边距：14~18px
- 区块间距：8~14px

## 5. 屏幕结构

### 5.1 主菜单

```
品牌 kicker
大标题
副标题
闯关进度条
4 条怎么玩
主按钮：闯关模式
次按钮：爬塔模式
最高进度
```

- 主按钮唯一高亮
- 进度条让玩家知道自己在哪
- 说明文案缩短，避免长教程

### 5.2 选关

```
10关闯关    已通关 0/10
选择关卡
逐关解锁 · 独立配球
进度条
2×5 关卡卡
返回主菜单
```

每张卡：

```
01
初试冰面
伤害 250 · 1球
可挑战 / ✓ 已通关 / 🔒 未解锁
```

- 当前可挑战卡片：冰蓝描边 + 轻辉光
- 已通关：绿色描边
- 未解锁：降低饱和度和透明度，但仍能读出内容

### 5.3 游戏 HUD

```
顶部左侧：得分 / 倍率 / 连击 / 门链
顶部右上：资源 / 选关 / 重开 / 声音
目标小胶囊：关卡名 + 目标 + 进度 + 壶数

底部左侧：冰球 chip
底部右侧：旋转分段控件
```

- 不再使用贯穿屏幕的上下横条
- 顶部目标压缩成约 **238×43** 的小胶囊，不压大本营
- 底部只有两个独立浮岛：冰球 chip 与旋转控件，高约 **54px**
- HUD 总高度约 **134px**
- 画布不再重复画 DEF 徽章/怪物黑球
- 提示文字从游戏区移除（菜单负责教学），Toast 放在左下角
- 操作区在下半屏，单手可达

### 5.4 弹层

- 统一卡片：深色玻璃、顶部高光、28px 圆角
- 主按钮固定在最下或最显眼位置
- 过关/失败不再堆叠无关信息
- 动效统一 280ms 上浮

### 5.5 结算

- 大标题：闯关成功 / 当前结果
- 统计行：到达关卡、最高通关、本关配球、最高冰球、当前目标
- 主按钮：选择关卡
- 分享为次操作

## 6. 视觉资产（Art Pass）

这轮不止改 UI，也把核心图像重画了一轮：

- **冰壶**：花岗岩径向高光、深色外圈、彩色环形带、金属/彩色手柄、顶部高光、旋转刻度、投影
- **钉子**：从平面圆点改成有厚度的立柱：白色柱身、红色环带、顶盖、左侧高光、底部冰面阴影
- **大本营**：同心冰环 + 外圈蓝光 + 冰面高光 + 中心准星，不再是一组纯色圆
- **增益门**：径向玻璃填充、外圈光晕、内圈玻璃线、金色 PERFECT 核心、中心十字
- **赛道**：冰面碎晶、长反射光、接缝线、hog line、侧板高光
- **背景**：极光带、场馆侧光、月晕
- **信息层**：HUD 不再重复画 DEF 徽章；关卡名进入目标条

### 6.1 遮挡修正

上一版 UI 的遮挡问题主要来自：

- 目标卡过高，压住大本营上半部
- 关卡开始 Toast 压住钉子
- 底部提示压在冰壶/赛道上

现在：

- 目标卡压缩成约 238×43 的小胶囊
- HUD 总高度从约 **166px 降到约 134px**
- 关卡开始不再弹 Toast；关卡名直接写进目标条
- 提示文字不再常驻游戏区
- Toast 改为左下角小胶囊，不再压大本营/中心钉子
- 画布上的 DEF 徽章删除，避免与 HUD 重复
- 底部不再有贯穿横条，改成左侧冰球 chip + 右侧旋转浮岛
- 冰壶、钉子、大本营全部在 HUD 下方可见

## 8. 抖音小游戏适配注意

抖音小游戏右上角有平台胶囊按钮，界面设计必须避开。

本原型当前仍把「选关 / 重开 / 声音」放在右上角，这是 Web 原型的布局。  
**迁移 Cocos / 抖音时必须做以下之一：**

1. 通过 `tt.getMenuButtonLayout()` / 安全区 API 获取胶囊位置，把 HUD 右上角让出
2. 把「选关 / 重开 / 声音」收进底部或左侧的菜单按钮，点击打开设置 sheet
3. 顶部右侧只保留不影响胶囊的状态信息

推荐最终方案：**底部 dock 左侧增加菜单按钮，低频操作收进 sheet**。  
这样顶部右侧完全交给平台，不抢胶囊。

同时：

- 使用 `tt.getSystemInfoSync().safeArea`
- 顶部/底部安全区动态适配
- 不在进入游戏 5 秒内弹隐私/授权弹窗
- Feed 直玩首屏应直接展示核心玩法，不先给纯菜单

参考：抖音开放平台屏幕适配、适配清单、Feed 直玩设计规范。

## 9. 可达性

- 所有按钮 ≥44×44
- `:focus-visible` 冰蓝描边
- `prefers-reduced-motion` 关闭 UI 动画
- 关键状态不只靠颜色：文字 + 图标 + 数值
- 触摸反馈在手指上方/旁边，不在手指正下方
- 文本最小 10px；主信息 11~12px
- 音频/震动可关闭；音量按静音按钮

## 10. 性能

- 弹层使用 `backdrop-filter`，但只覆盖弹层区域
- 避免全屏多层模糊叠加
- 关卡卡片使用 CSS，不引入图片资源
- 单文件构建保持无外部依赖
- Canvas 仍然固定 60Hz 更新
