# 爬塔模式 · 调研与设计草案

> 分支：`feature/tower-mode`
> 基线：`master` / `v0.3-baseline`，随时可回退（见 `ROLLBACK.md`）

## 1. 参考玩法

| 游戏/类型 | 核心机制 | 可借鉴点 |
|---|---|---|
| **魔塔 / Magic Tower** | 攻击力 > 怪物防御才能击杀；否则打不动 | “能不能打过”非常清晰，适合做层数门槛 |
| **Random Dice: Defense** | 合并相同骰子，提升攻击，抵御一波波怪物 | 合并=变强，短波次，成长可见 |
| **Merge Defense Adventures** | 数字塔防 + 合并，计算/预测 | 数字合并的爽感，低门槛 |
| **Merge Tower / Merge Defense 3D** | 合并炮塔/单位，守住波次 | 合并后战力立刻提升 |
| **《赵云与阿斗》** | 合并 + 塔防，抖音小游戏畅销榜 | 合并+塔防在抖音可行 |
| **《矮人爬爬塔》** | 点击/合并矮人军队，向上爬塔 | “爬塔”目标感与层数推进 |
| **Tank Defense: Merge Attack** | 合并部队，关卡推进 | 单位合并 + 关卡成长 |

### 调研结论

1. **合并必须有可见的战力提升**：合并前后数字/攻击力要立刻变化。
2. **层数门槛要清晰**：玩家一眼知道“我能不能打过这一层”。
3. **短局 + 快速重试**：失败不要惩罚太重，否则抖音用户直接退出。
4. **继承感是留存关键**：上一层的合并/强化要带到下一层。
5. **不要同时做两套复杂操作**：冰壶投掷已经是操作核心，爬塔只做“层间决策”。

## 2. 核心循环

```
选择爬塔
  → 第 N 层：怪物防御 DEF
  → 3 壶投掷，累计伤害 = 本层得分 × (1 + 攻击加成)
  → 伤害 ≥ DEF？
      是：突破 → 获得 1 颗石头 + 选择 1 个强化 → 合并/升级 → 下一层
      否：失去 1 心 → 重试本层（保留 build）
  → 3 心用完，本次爬塔结束
```

**和现有爽快模式的关系：**

- 爽快模式：3 壶冲 6,000 / 10,000，练手感。
- 爬塔模式：同样的 3 壶，但分数变成“伤害”，层数变成目标。
- 两套模式共用物理、门、钉子、计分；只在外层加“层数 / 防御 / 合并 / 强化”。

## 3. 数值草案

### 3.1 层数防御

| 层 | 怪物防御 | 玩家目标 |
|---|---|---|
| 1 | 2,000 | 熟悉流程，基本能过 |
| 2 | 3,100 | 需要至少 1 次合并 |
| 3 | 4,805 | 需要门链/倍率 |
| 4 | 7,448 | 需要 2 次合并 + 强化 |
| 5 | 11,544 | 第一次小考 |
| 6+ | ×1.55 / 层 | 无尽爬塔 |

> 初始 3 颗 L1 石头，攻击加成 0%；每层结束获得 1 颗 L1 石头。

### 3.2 石头合并

- 6 个槽位；初始 3 颗 L1。
- 两颗同等级合并为高一级。
- 每颗石头的攻击加成：

| 等级 | 单颗加成 |
|---|---|
| L1 | 0% |
| L2 | 10% |
| L3 | 30% |
| L4 | 70% |
| L5 | 150% |

公式：`bonus = 0.1 × (2^(L-1) - 1)`，多颗相加。

**示例：**

```
3 × L1 = 0%
合并 2 × L1 → L2：0% → 10%
再获得 1 × L1，合并 → L2：10% → 20%
两颗 L2 合并 → L3：20% → 30%
```

### 3.3 层间强化（3 选 1）

| 强化 | 效果 | 上限 |
|---|---|---|
| 加一壶 | 每层投掷数 +1 | 5 壶 |
| 攻击强化 | 攻击加成 +10% | 无 |
| 加一心 | 生命 +1 | 5 心 |
| 门强化（后续） | 指定门效果 +20% | 3 级 |

## 4. 失败与重试

- 每层 3 心。
- 伤害 < DEF：失去 1 心，**保留当前 build**，重试本层。
- 0 心：本次爬塔结束，显示到达层数 + 最高层数。
- 不做“看广告复活”MVP；后续可加。

## 5. UI

### 5.1 模式选择

主菜单：

```
[ 爽快模式 ]   3 壶冲高分
[ 爬塔模式 ]   一层一层变强
```

### 5.2 爬塔 HUD

- 第 N 层
- 怪物防御 DEF
- 伤害进度条：`当前伤害 / DEF`
- 攻击加成 `+X%`
- 心数 `❤❤❤`

### 5.3 层间界面

```
第 N 层突破！

伤害 4,200 / DEF 3,200

[石头槽]  L1  L1  L2  L1  [空]  [空]
         点击两颗同级石头合并

攻击加成 +10%

选择强化：
[ +1 壶 ]  [ +10% 攻击 ]  [ +1 心 ]

[ 进入第 N+1 层 ]
```

### 5.4 怪物

- 大本营后方一个冰雪守卫剪影 + DEF 徽章。
- 伤害达到 DEF 时碎裂/消失，进入下一层。
- MVP 用简单几何 + 粒子，不做复杂动画。

## 6. MVP 范围

- 爬塔模式独立入口，爽快模式不变。
- 5 层固定防御 + 之后无尽 ×1.55。
- 6 槽石头合并。
- 3 种强化（+1 壶 / +10% 攻击 / +1 心）。
- 3 心、失败重试、最高层数本地保存。
- 复用现有 3 排门 / 30 钉布局。
- 不做排行榜、广告、内购、皮肤。

## 7. 风险

| 风险 | 对策 |
|---|---|
| 两套模式让用户困惑 | 主菜单明确两个按钮；爬塔 HUD 明确“层/防御” |
| 层间界面太慢 | 合并一步、强化一步、下一层一步；支持点击继续 |
| 数值崩 | 先固定 5 层，记录每层通过率再调 |
| 合并无感 | 合并后立刻刷新攻击加成 + 震动/音效 |
| 破坏爽快模式 | 所有爬塔逻辑走 `mode === 'tower'` 分支；基线分支可回退 |
| 工作量大 | MVP 只做层数/防御/合并/强化，不做新门/新怪 |

## 8. 实施顺序

1. 控制层先改：按住蓄力、右上角重开、旋弧加大、收尾加速。
2. 爬塔模式：模式入口 + 层数/防御 + 伤害结算。
3. 合并界面 + 3 种强化。
4. 失败/重试/最高层。
5. 测试 + 文档 + 单文件构建。
6. 提交到 `feature/tower-mode`，`master` 保持 v0.3。
